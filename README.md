# Veyra ERP - الأساس الفعلي (Backend + Views)

أول شريحة **حقيقية وشغالة** من Veyra: قاعدة بيانات، ومنطق مخزن، وأوامر بيع وشراء، وقيود محاسبية، وصلاحيات، واعتماد بين المديولات.
النموذج الأمامي (`veyra_frontend_prototype.html`) هو المرجع للشكل. الشاشات هنا بسيطة بالتعمد، والشكل النهائي هيتبني عليها.

## التشغيل بنقرتين (أيقونة على سطح المكتب)

1. اضغط مرتين على `create_shortcut.bat` **مرة واحدة بس**: بيحط أيقونة **Veyra ERP** على سطح المكتب.
2. من بعد كده اضغط على الأيقونة: بتجهّز كل حاجة وتشغّل السيرفر وتفتح المتصفح لوحدها على http://127.0.0.1:8000. لإيقاف البرنامج اقفل الشاشة السودا.

أول مرة بتاخد دقيقة (بتنزّل المكتبات وتحمّل شركة التجربة)، وبعد كده بتفتح في ثواني. الأيقونة بتعمل `makemigrations` و`migrate` و`seed_modules` كل مرة (آمنة)، وبتحمّل بيانات التجربة **أول مرة بس** (عشان ما تصفّرش كلمات المرور اللي غيّرتها). لو السيرفر شغّال بالفعل، الأيقونة بتفتح المتصفح بس. لو نقلت مجلد المشروع، شغّل `create_shortcut.bat` تاني. ملف `start_veyra.bat` ممكن تشغّله مباشرة من غير الأيقونة.

## التشغيل على Windows

أسرع طريقة: شغّل `setup.bat` (بيجهّز البيئة، وبيعمل ملفات migrations، وبيطبّقها، وبيحمّل بيانات التجربة). أو يدويًا:

```powershell
py -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
python manage.py makemigrations accounts core inventory accounting sales purchasing
python manage.py migrate
python manage.py seed_modules
python manage.py seed_demo
python manage.py seed_owner
python manage.py runserver
```

**مهم عن migrations:** الأمر `makemigrations` لازم تذكر فيه أسماء التطبيقات (زي فوق) أول مرة، لأن المشروع مفيهوش ملفات migrations. بعد ما تتولّد، **ضيفها للمشروع واحفظها** (مجلدات `*/migrations/`)؛ Docker بيرفض يشتغل من غيرها. لو عندك migrations قديمة عندك على الجهاز، سيبها وشغّل `makemigrations` بنفس الأمر، هيضيف ملف جديد للتغييرات (الباركود وعلامة تغيير كلمة المرور) من غير ما يلمس القديم.

بعد كده افتح http://127.0.0.1:8000 وادخل بـ:
- **ahmed** / Demo@1234 (مدير الشركة، كل المديولات المفعّلة)
- **omar** / Demo@1234 (أمين مخزن، المخزون والباركود بس)

حساب مالك النظام (لوحة الإدارة http://127.0.0.1:8000/admin/): `python manage.py seed_owner` بيعمل حساب `admin` بكلمة مرور عشوائية بتظهر **مرة واحدة** وبيطلب منك تغييرها أول دخول. (أو `--password` لو عايز تحدد كلمة المرور بنفسك).

حساب `admin` ملوش شركة، فبيدخل لوحة الإدارة بس. لو عايزه يشوف التطبيق نفسه: `python manage.py enable_all_modules --user admin`.

بيانات التجربة (`seed_demo`) بترفض تشتغل لو `VEYRA_DEBUG=0`، عشان كلمات مرور حساباتها معروفة.

## الاختبارات

```powershell
python manage.py test
```

(لازم ملفات migrations تكون اتولّدت الأول، يعني شغّل `setup.bat` أو أمر `makemigrations` المذكور فوق قبل الاختبارات.)

بتغطي مديول المشتريات كامل (الموديل، التأكيد والاستلام والإلغاء والدفع، القيود، الفورمز، الشاشات والصلاحيات وعزل الشركات) بالإضافة لـ: الاعتمادات بين المديولات، صلاحيات المستخدم، منع الرصيد السالب، التسليم كله ينفع أو يترجع كله، منع التسليم والاستلام مرتين، تأكيد الأمر قبل التسليم، متوسط التكلفة، الباركود، البادئة في الترقيم، وإجبار تغيير كلمة المرور.

## سير الأمر (بيع وشراء)

`مسودة ← مؤكد ← تم التسليم / مستلم`. الأمر الجديد من الشاشة بيتعمل **مؤكد** مباشرة، والمسودة (من لوحة الإدارة) محتاجة زر "تأكيد الأمر" قبل التسليم أو الاستلام. التسليم والاستلام بيشتغلوا مرة واحدة بس حتى لو الزرار اتضغط مرتين. لو الشركة ملهاش مخزن، بيتعمل "المخزن الرئيسي" تلقائي.

## مديول المشتريات

`مسودة ← مؤكد (بانتظار الاستلام) ← مستلم`، ويتلغي (`ملغي`) قبل الاستلام بس.

| الإجراء | بيعمل إيه |
|---|---|
| **تأكيد الأمر** | ينقل المسودة لمؤكد (لازم فيه أصناف). |
| **استلام وإدخال للمخزن** | يدخل الكميات المخزن، ويحدّث متوسط تكلفة كل صنف، ويسجّل قيد المشتريات، ويحفظ **المستحق للمورد** (الإجمالي + الضريبة) في الأمر. كل ده في معاملة واحدة. |
| **إلغاء الأمر** | متاح للمسودة والمؤكد بس. الأمر المستلم عليه حركات مخزن وقيد فمينفعش يتلغي. |
| **تسجيل دفعة** | دفعة للمورد على أمر مستلم (نقدي أو تحويل بنكي)، بقيد مدين الموردين ودائن النقدية. مينفعش المبلغ يزيد عن المتبقي، وتقدر تدفع على دفعات. |

- حالة الدفع (غير مدفوع / مدفوع جزئيًا / مدفوع) بتظهر في قايمة الأوامر وفي تفاصيل الأمر، وفيه شاشة **مدفوعات الموردين** بكل الدفعات.
- **تسجيل دفعة** محتاج صلاحية المشتريات **والمحاسبة** مع بعض، لأنه بيعمل قيد محاسبي. أمين المشتريات اللي معاه المشتريات بس يشوف الدفعات ومش بيسجّلها.
- الأمر فيه **تاريخ الاستلام المتوقع** و**ملاحظات**.
- الدفعات للقراءة بس في لوحة الإدارة (بتتسجّل من الشاشة عشان كل دفعة ليها قيد)، والأمر اللي عليه دفعات مينفعش يتمسح.
- للاختبار: `python manage.py test purchasing`.

## دليل الحسابات (المحاسبة)

الدليل الافتراضي هو **الدليل المحاسبي الشامل بنمط Odoo: 132 حساب** (الأصول والالتزامات وحقوق الملكية والإيرادات والمصروفات)، منقول من ملف الدليل. كل شركة جديدة بيتحمّل لها الدليل لوحده أول ما تفتح «دليل الحسابات» أو أول قيد.

**الشاشة (المحاسبة ← دليل الحسابات):** شجرة مرتبة بالتدرج (111110 تحت 111100 تحت 110000 تحت 100000)، الحسابات التجميعية بخط عريض، وجنب كل حساب نوعه وطبيعته (مدين/دائن) والقائمة المالية ورصيده. الرصيد للحساب التجميعي بيجمع كل اللي تحته. فيه بحث بالكود أو الاسم وفلتر بالتصنيف، وضغطة على الحساب تفتح تفاصيله وآخر حركاته.

**اللي تقدر تعمله (للمدير):**
- **إضافة وتعديل** حساب: الكود أرقام (3 إلى 10 خانات) وفريد في الشركة، ولو سيبت «الحساب الرئيسي» فاضي بيتقترح أقرب حساب تجميعي بالكود. مينفعش الحساب يبقى تابع لنفسه أو لحاجة تحته، ومينفعش تغيّر كود حساب عليه قيود.
- **إيقاف** الحساب (بدل المسح): الحساب الموقوف مبيقبلش قيود جديدة وحركاته القديمة بتفضل.
- **مسح** الحساب: بيتمنع لو عليه قيود أو تحته حسابات فرعية أو مستخدم كحساب افتراضي.
- **الحسابات التجميعية** مبتقبلش قيود، والقيد على حساب تجميعي أو موقوف أو من شركة تانية بيترفض.
- **الحسابات الافتراضية** (المحاسبة ← الحسابات الافتراضية): بتحدد حساب كل دور (العملاء، الموردين، المخزون، ضريبة المدخلات والمخرجات، المبيعات، تكلفة البضاعة، الخزينة، البنك). القيود التلقائية بتستخدمها، فتقدر تغيّر الحساب من غير ما تلمس الكود. الدفعة النقدية للمورد بتروح للخزينة والتحويل البنكي للبنك.
- **تصدير واستيراد CSV:** التصدير متاح لكل من له صلاحية المحاسبة، والاستيراد للمدير. الأعمدة: `code, name, kind, nature, statement, parent_code, is_group, is_active, description` (`code` و`name` إجباريين، والباقي اختياري، وبيقبل الأسماء العربي للنوع والطبيعة والقائمة). الحساب الموجود بنفس الكود بيتعدّل والجديد بيتضاف ومفيش حاجة بتتمسح، ولو فيه أي خطأ مفيش حاجة بتتحفظ والأخطاء بتتعرض. أسهل طريقة: صدّر الدليل وعدّل عليه وارفعه.
- **تحميل الدليل الافتراضي** (زرار في أول القايمة، أو `python manage.py load_chart --company كود_الشركة` أو `--all`): بيضيف أي حسابات ناقصة بس، ومبيعدّلش ولا يمسح حاجة.

**ملاحظات:**
- ميزان المراجعة بيعرض الحسابات اللي عليها حركة بس (زرار لإظهار الكل).
- الشركات اللي كان عندها الدليل القديم (أكواد من 4 أرقام زي 1300 و2100) بتتحول تلقائيًا: القيود القديمة بتتنقل للحسابات الجديدة المقابلة، وأي حساب أنت عملته بنفسك مبيتلمسش.
- أنواع الحسابات والطبيعة والقائمة المالية زي ما هي في ملف الدليل (فيه حسابات نوعها في الملف يبدو غريب زي «تسجيل العلامات التجارية» كأصول متداولة)، وتقدر تعدّلها من الشاشة.
- بعد التحديث شغّل `makemigrations` (أيقونة التشغيل بتعملها لوحدها) عشان الحقول والجداول الجديدة.
- الاختبارات: `python manage.py test accounting`.

## الباركود

- الصنف ليه حقل **الباركود** (فريد جوه الشركة، الفاضي مسموح). بيتضاف ويتعدّل من شاشة الصنف (زر تعديل في صفحة الصنف).
- في قايمة المنتجات: امسح الباركود في خانة البحث والصنف هيظهر.
- في أوامر البيع والشراء: كل سطر فيه خانة **باركود**. امسح الباركود (أو اختار الصنف بإيدك)، اكتب الكمية، والسعر بيتملى من الصنف لو سيبته فاضي (سعر البيع للمبيعات، وتكلفة الصنف للمشتريات).

## الإعدادات اللي شغّالة فعلًا

| الإعداد | بيأثر على |
|---|---|
| `sales.prefix` و`purchasing.prefix` | ترقيم الأوامر الجديدة |
| `sales.tax_rate` | ضريبة المخرجات عند التسليم |
| `accounting.default_purchase_tax` | ضريبة المدخلات عند الاستلام |
| `inventory.allow_negative` | السماح بالصرف على الرصيد السالب |
| `settings.company_name` | الافتراضي = اسم الشركة نفسها |

باقي الإعدادات في الشاشة (الموافقات، FIFO، الأرقام التسلسلية...) **تصميم لخطوات جاية**: بتتحفظ لكن الكود لسه مبيستخدمهاش.

متوسط تكلفة الصنف (**متوسط مرجح**) بيتحدّث مع كل استلام شراء، وبيتحسب منه تكلفة البضاعة المباعة في القيد.

## القواعد اللي اتبنى عليها الكود

1. **الرصيد = مجموع دفتر الحركات** (`StockMove`)، ومفيش رقم بيتعدل بإيده.
2. **كل عملية تغيّر المخزن بتتم في معاملة واحدة** (`transaction.atomic`)، ولو صنف واحد فشل، كل العملية بتترجع.
3. **قفل صف الصنف** (`select_for_update`) عشان عمليتين في نفس اللحظة ما يصرفوش نفس الكمية (على PostgreSQL). وتغيير حالة الأمر (تسليم/استلام) بيتم بخطوة واحدة بشرط الحالة، فبيشتغل على SQLite وPostgreSQL.
4. **كل سجل مربوط بالشركة**، وكل شاشة بتفلتر بيها. مستخدم شركة مش هيشوف بيانات شركة تانية.
5. **المديول لازم يكون مفعّل للشركة ومسموح للمستخدم** قبل ما يفتح شاشته (`module_required`).
6. **المديول مش بيتفعّل إلا لو اعتماداته مفعّلة**، والمديول اللي حد محتاجه مش بيتعطل.
7. **كل قيد محاسبي متوازن**، ومبيتكررش لنفس المستند.

## تشغيل بضغطة واحدة (أيقونة سطح المكتب)

1. دوس مرتين على `create_shortcut.bat` (مرة واحدة بس): هيحط أيقونة **Veyra ERP** على سطح المكتب.
2. بعد كده دوس على الأيقونة. أول مرة بتجهّز البيئة (كام دقيقة)، وبعدها بياخد ثواني. بيشغّل `makemigrations` و`migrate` و`seed_modules` و`enable_all_modules` و`runserver` وبيفتح المتصفح لوحده.
3. سيب النافذة السودا مفتوحة وإنت شغال، وقفلها لما تخلص.

لو غيّرت مكان المجلد شغّل `create_shortcut.bat` تاني. الملف ده للتطوير على جهازك (SQLite) مش للنشر. وفي أول `start_veyra.bat` إعداد `ENABLE_ALL` (1 = يفعّل كل المديولات في كل تشغيل، 0 = أول مرة بس).

## التحويل إلى PostgreSQL (اختياري)

الكود جاهز للتبديل بمتغيرات البيئة، وملفات migrations مش مرتبطة بنوع القاعدة.

1. نزّل PostgreSQL من postgresql.org (المثبّت الرسمي) واحفظ كلمة سر المستخدم `postgres` اللي بتختارها وقت التثبيت.
2. من قايمة Start افتح **SQL Shell (psql)**: دوس Enter على الأسئلة الأربعة الأولى (Server وDatabase وPort وUsername) واكتب كلمة السر (مش بتظهر وانت بتكتبها). لما يظهر `postgres=#` اكتب الأمرين **واحد واحد**:

```sql
CREATE USER veyra WITH PASSWORD 'MyStrongPass_2026';
CREATE DATABASE veyra OWNER veyra;
```

   كل أمر لازم ينتهي بـ `;` وتدوس Enter، ولازم يرد `CREATE ROLE` ثم `CREATE DATABASE`. اختار كلمة سر بحروف إنجليزي وأرقام بدون علامة `'`. ولو استخدمت pgAdmin بدل psql، حدد كل أمر لوحده واضغط F5 (أمر `CREATE DATABASE` مبيشتغلش لو اتبعت مع أمر تاني في نفس التنفيذ). كلمة `OWNER veyra` مهمة، من غيرها الـmigrations ممكن تفشل في PostgreSQL الجديد. للتأكد: `\du` يعرض المستخدمين و`\l` يعرض القواعد، وللخروج `\q`.
3. في PowerShell جوه مجلد المشروع:

```powershell
$env:VEYRA_DB="postgres"
$env:PG_PASSWORD="MyStrongPass_2026"
python manage.py migrate
python manage.py seed_modules
python manage.py seed_demo
python manage.py runserver
```

ملاحظات: بيانات PostgreSQL بتفضل على الجهاز اللي متثبّت عليه (مش بتتنقل مع مجلد المشروع زي `db.sqlite3`)، فلو بتشتغل على جهازين كرر الخطوتين 1 و2 على الجهاز التاني. و`start_veyra.bat` الحالي مصمم لـSQLite ومحتاج تعديل قبل ما يشتغل مع PostgreSQL.

## قاعدة بيانات سحابية (Neon) بدل SQLite

مفيد لو بتشتغل على أكتر من جهاز: القاعدة واحدة على الإنترنت، والبيانات بتفضل زي ما هي في أي جهاز تفتح منه.

1. من Neon Console (زرار **Connect**) انسخ رابط الاتصال. **استخدم الرابط المباشر**: اسم السيرفر من غير `-pooler` (Neon بتوصي بيه للـmigrations).
2. اعمل ملف اسمه `.env` في مجلد المشروع جنب `manage.py` وحط فيه سطر واحد (الأسهل من PowerShell جوه المجلد):

```powershell
@"
DATABASE_URL=postgresql://USER:PASSWORD@ep-xxxx.region.aws.neon.tech/neondb?sslmode=require&channel_binding=require
"@ | Set-Content -Encoding utf8 .env
```

3. شغّل الأيقونة (`start_veyra.bat`) أو `python manage.py migrate` وبعدين `seed_modules` و`seed_demo` و`runserver`. البرنامج بيقرا `.env` لوحده، وبيحمّل بيانات التجربة بس لو القاعدة فاضية.

ملاحظات:
- ملف `.env` فيه كلمة سر القاعدة: **ماتشاركوش ومتحطوش في zip**. لو الرابط اتنشر في أي مكان، غيّر كلمة السر من Neon (Reset password) وحدّث `.env`.
- لو فيه `DATABASE_URL`، هو اللي بيتستخدم. للرجوع لـSQLite امسح السطر ده أو سمّي الملف باسم تاني.
- القاعدة المشتركة معناها إن ملفات `migrations/` لازم تكون **نفسها** على الجهازين. ماتسيبش كل جهاز يولّدها لوحده: انقل مجلدات `*/migrations/` مع المشروع (أو استخدم git).
- أول طلب بعد فترة خمول ممكن يتأخر ثواني (Neon بتوقف الحساب لما مفيش استخدام). والأيقونة بتشغّل كذا أمر على القاعدة في كل تشغيل فهتاخد وقت أطول من SQLite.
- لو استخدمت الرابط اللي فيه `-pooler` البرنامج بيظبط نفسه (بيقفل server-side cursors)، لكن للـmigrations استخدم المباشر.

## النشر بـ Docker

```powershell
copy .env.example .env      # واملا PG_PASSWORD وVEYRA_SECRET_KEY
docker compose up --build
```

الحاوية بتشغّل `migrate` لوحدها وقت التشغيل، وبترفض تشتغل لو ملفات migrations ناقصة أو مش مطابقة للموديلات. السيرفر بيرفض يشتغل بـ `VEYRA_DEBUG=0` من غير `VEYRA_SECRET_KEY` حقيقي. خلف HTTPS: فعّل `VEYRA_HTTPS=1` وحط الدومين في `VEYRA_CSRF_ORIGINS`.

لإنشاء حساب مالك النظام على السيرفر: `docker compose exec web python manage.py seed_owner`.
المديولات الأساسية لازم تتحمّل مرة: `docker compose exec web python manage.py seed_modules`.

## اللي مش موجود بعد (الخطوات الجاية)

- نموذج الواجهة الكامل (الشكل من النموذج الأمامي) داخل Django templates.
- لوحة المنصة الحقيقية (شركات، اشتراكات، معاينة) مربوطة بالقاعدة.
- **قرار معماري محتاج حسم:** كل الشركات حاليًا في قاعدة بيانات واحدة وكل سجل عليه `company`. لو الخطة قاعدة بيانات منفصلة لكل شركة، لازم تتحسم بدري.
- التحقق بخطوتين، والسحب والإفلات في الشاشات، والإشعارات، والشات.
- باقي المديولات (التصنيع، الجودة، الموارد البشرية...) وتفعيل باقي الإعدادات.
- WeasyPrint (الطباعة PDF) للإنتاج.
