# Veyra ERP - الأساس الفعلي (Backend + Views)

أول شريحة **حقيقية وشغالة** من Veyra: قاعدة بيانات، ومنطق مخزن، وأوامر بيع وشراء، وقيود محاسبية، وصلاحيات، واعتماد بين المديولات.
النموذج الأمامي (`veyra_frontend_prototype.html`) هو المرجع للشكل. الشاشات هنا بسيطة بالتعمد، والشكل النهائي هيتبني عليها.

## التشغيل على Windows

أسرع طريقة: شغّل `setup.bat` (بيجهّز البيئة، وبيعمل ملفات migrations، وبيطبّقها، وبيحمّل بيانات التجربة). أو يدويًا:

```powershell
py -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
python manage.py makemigrations accounts core inventory accounting sales purchasing
python manage.py migrate
python manage.py seed_modules
python manage.py seed_demo
python manage.py seed_owner
python manage.py runserver
```

**مهم عن migrations:** الأمر `makemigrations` لازم تذكر فيه أسماء التطبيقات (زي فوق) أول مرة، لأن المشروع مفيهوش ملفات migrations. بعد ما تتولّد، **ضيفها للمشروع واحفظها** (مجلدات `*/migrations/`)؛ Docker بيرفض يشتغل من غيرها. لو عندك migrations قديمة عندك على الجهاز، سيبها وشغّل `makemigrations` بنفس الأمر، هيضيف ملف جديد للتغييرات (الباركود وعلامة تغيير كلمة المرور) من غير ما يلمس القديم.

بعد كده افتح http://127.0.0.1:8000 وادخل بـ:
- **ahmed** / Demo@1234 (مدير الشركة، كل المديولات المفعّلة)
- **omar** / Demo@1234 (أمين مخزن، المخزون والباركود بس)

حساب مالك النظام (لوحة الإدارة http://127.0.0.1:8000/admin/): `python manage.py seed_owner` بيعمل حساب `admin` بكلمة مرور عشوائية بتظهر **مرة واحدة** وبيطلب منك تغييرها أول دخول. (أو `--password` لو عايز تحدد كلمة المرور بنفسك).

حساب `admin` ملوش شركة، فبيدخل لوحة الإدارة بس. لو عايزه يشوف التطبيق نفسه: `python manage.py enable_all_modules --user admin`.

بيانات التجربة (`seed_demo`) بترفض تشتغل لو `VEYRA_DEBUG=0`، عشان كلمات مرور حساباتها معروفة.

## الاختبارات

```powershell
python manage.py test
```

(لازم ملفات migrations تكون اتولّدت الأول، يعني شغّل `setup.bat` أو أمر `makemigrations` المذكور فوق قبل الاختبارات.)

بتغطي: الاعتمادات بين المديولات، صلاحيات المستخدم، منع الرصيد السالب، التسليم كله ينفع أو يترجع كله، منع التسليم والاستلام مرتين، تأكيد الأمر قبل التسليم، متوسط التكلفة، الباركود، البادئة في الترقيم، وإجبار تغيير كلمة المرور.

## سير الأمر (بيع وشراء)

`مسودة ← مؤكد ← تم التسليم / مستلم`. الأمر الجديد من الشاشة بيتعمل **مؤكد** مباشرة، والمسودة (من لوحة الإدارة) محتاجة زر "تأكيد الأمر" قبل التسليم أو الاستلام. التسليم والاستلام بيشتغلوا مرة واحدة بس حتى لو الزرار اتضغط مرتين. لو الشركة ملهاش مخزن، بيتعمل "المخزن الرئيسي" تلقائي.

## الباركود

- الصنف ليه حقل **الباركود** (فريد جوه الشركة، الفاضي مسموح). بيتضاف ويتعدّل من شاشة الصنف (زر تعديل في صفحة الصنف).
- في قايمة المنتجات: امسح الباركود في خانة البحث والصنف هيظهر.
- في أوامر البيع والشراء: كل سطر فيه خانة **باركود**. امسح الباركود (أو اختار الصنف بإيدك)، اكتب الكمية، والسعر بيتملى من الصنف لو سيبته فاضي (سعر البيع للمبيعات، وتكلفة الصنف للمشتريات).

## الإعدادات اللي شغّالة فعلًا

| الإعداد | بيأثر على |
|---|---|
| `sales.prefix` و`purchasing.prefix` | ترقيم الأوامر الجديدة |
| `sales.tax_rate` | ضريبة المخرجات عند التسليم |
| `accounting.default_purchase_tax` | ضريبة المدخلات عند الاستلام |
| `inventory.allow_negative` | السماح بالصرف على الرصيد السالب |
| `settings.company_name` | الافتراضي = اسم الشركة نفسها |

باقي الإعدادات في الشاشة (الموافقات، FIFO، الأرقام التسلسلية...) **تصميم لخطوات جاية**: بتتحفظ لكن الكود لسه مبيستخدمهاش.

متوسط تكلفة الصنف (**متوسط مرجح**) بيتحدّث مع كل استلام شراء، وبيتحسب منه تكلفة البضاعة المباعة في القيد.

## القواعد اللي اتبنى عليها الكود

1. **الرصيد = مجموع دفتر الحركات** (`StockMove`)، ومفيش رقم بيتعدل بإيده.
2. **كل عملية تغيّر المخزن بتتم في معاملة واحدة** (`transaction.atomic`)، ولو صنف واحد فشل، كل العملية بتترجع.
3. **قفل صف الصنف** (`select_for_update`) عشان عمليتين في نفس اللحظة ما يصرفوش نفس الكمية (على PostgreSQL). وتغيير حالة الأمر (تسليم/استلام) بيتم بخطوة واحدة بشرط الحالة، فبيشتغل على SQLite وPostgreSQL.
4. **كل سجل مربوط بالشركة**، وكل شاشة بتفلتر بيها. مستخدم شركة مش هيشوف بيانات شركة تانية.
5. **المديول لازم يكون مفعّل للشركة ومسموح للمستخدم** قبل ما يفتح شاشته (`module_required`).
6. **المديول مش بيتفعّل إلا لو اعتماداته مفعّلة**، والمديول اللي حد محتاجه مش بيتعطل.
7. **كل قيد محاسبي متوازن**، ومبيتكررش لنفس المستند.

## الهيكل

| المسار | المحتوى |
|---|---|
| `veyra/` | الإعدادات والروابط |
| `core/` | الشركات، المديولات والاعتمادات بينها، الشركاء (عملاء/موردين)، الكتالوج، الإعدادات، شاشات الرئيسية |
| `accounts/` | المستخدم مربوط بالشركة، مدير أو مستخدم، والمديولات المسموحة |
| `inventory/` | المخازن، الأصناف (بالباركود)، دفتر الحركات، خدمات الاستلام والصرف ومتوسط التكلفة |
| `sales/` | أوامر البيع، والتسليم اللي بيخصم من المخزن |
| `purchasing/` | أوامر الشراء، والاستلام اللي بيدخل المخزن |
| `accounting/` | دليل الحسابات، القيود اليومية، ميزان المراجعة |
| `templates/` | الشاشات (عربي RTL، خط Cairo) |

## النشر بـ Docker

```powershell
copy .env.example .env      # واملا PG_PASSWORD وVEYRA_SECRET_KEY
docker compose up --build
```

الحاوية بتشغّل `migrate` لوحدها وقت التشغيل، وبترفض تشتغل لو ملفات migrations ناقصة أو مش مطابقة للموديلات. السيرفر بيرفض يشتغل بـ `VEYRA_DEBUG=0` من غير `VEYRA_SECRET_KEY` حقيقي. خلف HTTPS: فعّل `VEYRA_HTTPS=1` وحط الدومين في `VEYRA_CSRF_ORIGINS`.

لإنشاء حساب مالك النظام على السيرفر: `docker compose exec web python manage.py seed_owner`.
المديولات الأساسية لازم تتحمّل مرة: `docker compose exec web python manage.py seed_modules`.

## اللي مش موجود بعد (الخطوات الجاية)

- نموذج الواجهة الكامل (الشكل من النموذج الأمامي) داخل Django templates.
- لوحة المنصة الحقيقية (شركات، اشتراكات، معاينة) مربوطة بالقاعدة.
- **قرار معماري محتاج حسم:** كل الشركات حاليًا في قاعدة بيانات واحدة وكل سجل عليه `company`. لو الخطة قاعدة بيانات منفصلة لكل شركة، لازم تتحسم بدري.
- التحقق بخطوتين، والسحب والإفلات في الشاشات، والإشعارات، والشات.
- باقي المديولات (التصنيع، الجودة، الموارد البشرية...) وتفعيل باقي الإعدادات.
- WeasyPrint (الطباعة PDF) للإنتاج.
