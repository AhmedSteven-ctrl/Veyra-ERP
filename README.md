# Veyra ERP - الأساس الفعلي (Backend + Views)

هذا المشروع أول شريحة **حقيقية وشغالة** من Veyra: قاعدة بيانات، ومنطق مخزن، وأوامر بيع وشراء، وصلاحيات، واعتماد بين المديولات.
النموذج الأمامي (`veyra_frontend_prototype.html`) هو المرجع للشكل. الشاشات هنا بسيطة بالتعمد، والشكل النهائي هيتبني عليها.

## التشغيل على Windows

```powershell
py -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
python manage.py migrate
python manage.py seed_modules
python manage.py seed_demo
python manage.py runserver
```

بعد كده افتح http://127.0.0.1:8000 وادخل بـ:
- **ahmed** / Demo@1234 (مدير، كل المديولات المفعّلة)
- **omar** / Demo@1234 (أمين مخزن، المخزون والباركود بس)

لوحة الإدارة: `python manage.py createsuperuser` وبعدها http://127.0.0.1:8000/admin/

## الاختبارات

```powershell
python manage.py test
```

الاختبارات بتغطي: الاعتمادات بين المديولات، صلاحيات المستخدم، منع الرصيد السالب، وإن التسليم كله ينفع أو يترجع كله.

## القواعد اللي اتبنى عليها الكود

1. **الرصيد = مجموع دفتر الحركات** (`StockMove`)، ومفيش رقم بيتعدل بإيده.
2. **كل عملية تغيّر المخزن بتتم في معاملة واحدة** (`transaction.atomic`)، ولو صنف واحد فشل، كل العملية بتترجع.
3. **قفل صف الصنف** (`select_for_update`) عشان عمليتين في نفس اللحظة ما يصرفوش نفس الكمية (على PostgreSQL).
4. **كل سجل مربوط بالشركة**، وكل شاشة بتفلتر بيها. مستخدم شركة مش هيشوف بيانات شركة تانية.
5. **المديول لازم يكون مفعّل للشركة ومسموح للمستخدم** قبل ما يفتح شاشته (`module_required`).
6. **المديول مش بيتفعّل إلا لو اعتماداته مفعّلة**، والمديول اللي حد محتاجه مش بيتعطل.

## الهيكل

| المسار | المحتوى |
|---|---|
| `veyra/` | الإعدادات والروابط |
| `core/` | الشركات، المديولات والاعتمادات بينها، الشركاء (عملاء/موردين)، الكتالوج، شاشات الرئيسية |
| `accounts/` | المستخدم مربوط بالشركة، مدير أو مستخدم، والمديولات المسموحة |
| `inventory/` | المخازن، الأصناف، دفتر الحركات، خدمات الاستلام والصرف |
| `sales/` | أوامر البيع، والتسليم اللي بيخصم من المخزن |
| `purchasing/` | أوامر الشراء، والاستلام اللي بيدخل المخزن |
| `templates/` | الشاشات (عربي RTL، خط Cairo) |

## اللي مش موجود بعد (الخطوات الجاية)

- القيود المحاسبية من المشتريات والمبيعات (المحاسبة).
- إنشاء أوامر البيع والشراء من الشاشة (دلوقتي من لوحة الإدارة).
- نموذج الواجهة الكامل (الشكل من النموذج الأمامي) داخل Django templates.
- لوحة المنصة الحقيقية (شركات، اشتراكات، معاينة) مربوطة بالقاعدة.
- التحقق بخطوتين، والسحب والإفلات في الشاشات، والإشعارات، والشات.
- باقي المديولات (التصنيع، الجودة، الموارد البشرية...).
- PostgreSQL وWeasyPrint (الطباعة PDF) للإنتاج.

## ملاحظات

- كلمات السر في `seed_demo` للتجربة المحلية بس، ولازم تتغير قبل أي نشر.
- `VEYRA_SECRET_KEY` لازم تتحط في البيئة قبل النشر، ومعاها `VEYRA_DEBUG=0`.
- للتحويل لـ PostgreSQL: `VEYRA_DB=postgres` مع متغيرات `PG_*`.
